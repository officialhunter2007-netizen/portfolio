Keyless CI/CD to ECS Fargate

Every push to main is linted, tested, scanned and deployed to ECS Fargate. GitHub authenticates to AWS with short-lived OIDC credentials, so there are no AWS keys stored anywhere.

The problem

My earlier projects were built by hand or from the CLI. I wanted the whole path from git push to a running container to be automatic, repeatable and safe: no manual steps, no long-lived credentials that could leak, and a way to find out when something breaks before users do.

Architecture

The pipeline

Every step runs on ubuntu-latest; any failure stops the run before anything reaches AWS production resources.

  1. Lint: flake8 on the app.
  2. Test: pytest against the Flask endpoints.
  3. Authenticate: aws-actions/configure-aws-credentials exchanges GitHub's signed OIDC token for temporary AWS credentials. No access keys exist in the repository or in GitHub secrets.
  4. Build: Docker image tagged with the commit SHA.
  5. Scan: Trivy fails the run on any fixable CRITICAL vulnerability, before the image is pushed.
  6. Push: the image goes to ECR, whose tags are immutable.
  7. Deploy: the current task definition is downloaded, the image is swapped in, a new revision is registered, and the service does a rolling update. The step waits for service stability.

Engineering decisions

OIDC instead of stored access keys

A leaked long-lived key is a permanent breach. OIDC credentials are temporary and bound to one repository by the role's trust policy.

Least-privilege deploy role

The pipeline role can push only to this ECR repository, update only this one ECS service, and pass only the task role. A few read and register actions (such as ecs:RegisterTaskDefinition) cannot be resource-scoped and use *.

Private tasks, layered network rules

Tasks run in private subnets with no public IP. The ALB security group accepts ports 80 and 443 from anywhere; the ECS security group accepts port 5000 only from the ALB's security group.

Immutable ECR tags

A tag can never be overwritten, so a bad build cannot replace the image you would roll back to. A lifecycle policy keeps the last 10 images.

One NAT gateway, on purpose

One per AZ would be highly available; I chose one to keep cost down for a lab. If its AZ fails, tasks in the other AZ lose outbound internet. In a revenue-critical system I would add the second.

Terraform split by concern

Nine files (vpc, ecs, alb, iam, ecr, cloudwatch…) so each change has one obvious home.

Alert before users notice

The ALB checks /health every 30 s. A CloudWatch alarm on UnHealthyHostCount > 0 (60 s period) publishes to an SNS topic that emails me.

Issues I hit and fixed

  • OIDC role would not assume

    Cause: GitHub's sub claim for newer repositories includes numeric owner and repository IDs, so my repo:owner/repo:* condition never matched.

    How I found it: added a debug step to decode the token's real claims.

    Fix: updated the trust policy condition to the numeric-ID format.

  • Trivy blocked on vulnerabilities with no patch

    Cause: critical CVEs in a base-image package had no fixed version available, so failing the build could not be acted on.

    Fix: added --ignore-unfixed so the gate fails only when a fix exists.

  • Terraform artifacts committed to Git

    Cause: no .gitignore before the first commit, so state and the provider binary were tracked (the provider far exceeds GitHub's file-size limit).

    Fix: rewrote history to remove them, added a proper .gitignore. Lesson: ignore first, and use remote state.

Limitations and what I would do next

Scope. This is a self-directed lab, not a production system, and no live endpoint is published.

  • Local Terraform state. No remote backend or locking yet; next step is an S3 backend with state locking.
  • HTTP only. The ALB has a port-80 listener; adding ACM, a domain and an HTTPS listener is the next step.
  • Trivy runs from aquasec/trivy:latest. I would pin it to a version or digest so the scanner itself is reproducible.
  • Secrets. The task role can read one Secrets Manager path, but the task definition in Terraform does not yet inject a secret into the container.
  • One NAT gateway (see decisions above).
